# TinyIMX Qt6 0.3 功能完善与问题复盘

2026-10-07。本轮目标是在正常服务器上完成原生 Windows 客户端的群组、文件与 AI 业务链路，并验证功能衔接。后端容量压测保持暂停。使用本机现有 Qt 6.10.2 MinGW 64，专用测试账号 750004–750006，正常演示账号 750001–750003 保留。

## 最终交付

Qt `LiveStore` 默认连接真实 TIMX；群控制和消息复用现有协议；新增群历史 gRPC 追加在原方法之后，保持既有方法序号兼容。独立 C++ 文件入口通过现有 User/Group/File/Message gRPC 服务完成认证、文件数据和群历史，文件字节不进入聊天 Gateway/RocketMQ 队列。AI 直接使用本机 Ollama 的真实 `/api/chat` 流式生成。

| 领域 | 完成的交互及确认 |
|---|---|
| 账号/私聊 | 三账号并行认证、本人信息、好友申请/接受/拒绝/删除、私聊入库确认、实时 ACK、MID/CID 去重、原 CID 重试、历史、离线补投、私聊已读/未读；与新功能共同回归 |
| 群组/群聊 | 创建、开放加入、邀请、移出、角色、禁言/解除、版本化资料修改、转让、退出/解散；群组和成员分页；群消息存储与双接收者投递；会话键 `g:ID` 与私聊用户 ID 分离 |
| 群历史 | 当前成员校验、仅本人发送或原始持久化投递收件人的消息、MID 排序/游标/限额检查；重新登录恢复且后入群用户看不到此前未投递给自己的内容 |
| 上传/分享 | 原生选择文件、分块和整文件 SHA-256、幂等上传 ID、服务器缺块恢复、暂停/续传、终验后才发送附件；私聊用户/群组绑定的签名下载能力 |
| 下载/恢复 | 分范围 SHA、身份/偏移检查、整文件异步终验、唯一文件名和新建模式、无覆盖发布；任务按账号和入口保存；错误记录与 `.part` 保留；损坏文件新任务重试 |
| 取消 | 已有上传 ID 时等待服务器 ACK；Begin 正在执行时保存迟到 ID 并继续取消，不提前显示成功；取消未确认的任务恢复后可重试取消 |
| AI | 服务/模型检测、真实流式回答、取消和错误处理、可选已加载会话片段、登出清空；AI 期间继续私聊；附件上下文仅使用显示文件名 |
| 多入口会话 | 修复跨网关旧连接 presence epoch 已被替换却仍保持认证；在旧心跳确认 Redis kMismatch 后安全通知和关闭原连接，保护新会话 |

当前已验证版本和所有公开检查名称以 `clients/qt6/validation/FEATURES_20261007.json` 为准。正常使用见 [启动指南](NORMAL_SERVER_WINDOWS_CLIENT_20261007.md)。真实界面截图在 `clients/qt6/preview-features/`。

## 核验方式和解释

验收同时核对服务 ACK、真实收件消息、重新登录后的持久化历史、权限拒绝以及文件字节，不以按钮可点击或进度动画作为完成证据。最终 exe 使用独立证据目录，检查退出码和 Qt stderr。原生截图来自同一个已认证应用的 QQuickWindow，不是浏览器重画。

| 检查 | 证据与重点 |
|---|---|
| 原生功能整链 | 最终 `qt6-features-e2e-*`；群角色/禁言/成员变化、历史快照、AI 与聊天、私聊/群聊附件、暂停/续传、账号任务恢复、取消 Begin 竞态、损坏下载拒绝并重试、文件历史和预览 |
| 原有私聊回归 | 最终 `qt6-features-private-regression-*`，31 项；错误密码、三连接、好友与私聊、多行/Unicode、ACK/已读、离线/历史、本机账号排他、截图和退出 |
| 文件入口 | `qt6-file-ingress-e2e-attempt3`，37 项；未登录、身份派生、actor 注入、跨账号访问、乱序块、重复块、哈希与范围、能力篡改、错误接收者、取消和登出令牌撤销 |
| 跨网关会话 | `cross-gateway-report.json`，6 项；旧连接收到替换通知并 EOF，新连接好友 RPC 和心跳在旧连接清理后继续成功 |
| C++ 后端 | MessageApplication 与 gRPC 集成两个 CTest 目标通过；新增 7 个群历史参数、排序、游标、结果身份与错误传播用例 |
| Qt 本地契约 | Demo 状态 19 项、TIMX codec 15 项；包含分包/粘包、64 位 ID、异常头、超长帧、非对象 JSON 与拒绝内部协议；8 张设计页面截图、0 Qt 警告 |

文件终验使用 2 MiB 的本任务合成二进制，接收结果与原字节完全一致。取消竞态在 Begin 请求已提交而 ID 未返回时触发。损坏测试只改本任务证据目录的暂停下载 `.part`，校验拒绝后保留失败文件并另建任务，成功结果再与原字节比较。

跨网关一次显式旧心跳后约 6.54 ms 收到替换通知是功能观测，不能当容量或 p99 结论；普通客户端心跳间隔 5 秒。模型采用已授权下载的 qwen3:0.6b，小模型真实可生成不等于答案质量或 AI 并发指标已经优秀。

## 问题、瓶颈原因与修正记录

| 问题/失败 | 准确原因 | 修正与保留证据 |
|---|---|---|
| 群/文件/AI 页面仍停留设计样例 | 缺少真实客户端 RPC、文件授权/数据入口与本机模型 | 独立 LiveGroups/LiveFiles/LiveAI 页面，实际账号和真实服务完成验收；原 Demo 保留用于隔离预览 |
| 群重新登录缺少历史 | 现有群协议仅有实时消息；不能靠本进程缓存代表持久化 | 添加 ListGroupHistory 应用/仓库/RPC，当前成员加原投递快照 ACL；回归验证后入群不泄漏旧消息 |
| 首次禁言验证失败 | 客户端发送 SQL 时间串，而群服务要求 RFC3339 | 发送 Qt ISODateWithMs UTC，解析返回 UTC；保留 `qt6-features-e2e-attempt1` |
| 首次完整 Qt 编译失败 | 测试调用了 RowModel 不存在的 C++ count() | 使用 rowCount()；`qt6-ui-features-20261007-attempt2` 源快照和编译日志保留 |
| 文件 Begin 被拒绝 | 64 KiB 上传块低于 FileService 256 KiB 最小契约 | 上传统一 256 KiB，HTTP 请求容量同步允许 Base64 开销，下载仍 64 KiB；入口和客户端失败/修正轮次均保留 |
| 错误所有者测试预期不符 | 服务对无权限对象返回 404 隐藏其存在，测试仅接受 403 | 验证 403/404 都是拒绝，并继续检查无法读元数据/字节；不改变服务器保密语义 |
| 重新登录传输任务丢失 | disconnectSession 保存后未清空 journal 路径，后一次清理用空 tasks 覆盖旧记录 | 保存后清 journal/actor；账号分域、会话代次过滤旧回调、损坏日志拒绝覆盖；保留原生 attempt3，后续恢复通过 |
| 取消早于上传 ID 会留下活动会话 | 一般任务代次过滤丢弃迟到 Begin 响应，客户端提前显示取消 | 幂等 Begin 的持久化 ID 特别记账，cancel_requested 等待并完成服务器取消；新原生竞态检查通过 |
| 大文件整体验证阻塞 UI 的风险 | 同步读完整下载文件进行 SHA 占据 GUI 线程 | 256 KiB 每个事件循环片段异步哈希；传输期间可操作和停止；范围和整文件校验均保留 |
| 损坏 `.part` 重试循环失败 | 从原偏移继续不能修复已经写坏的早期字节 | 整文件哈希失败标记 restart_required；新唯一任务重新下载，保留原失败文件；主动改动合成文件的回归通过 |
| 会话预览出现能力 JSON | 附件 wire payload 被直接用于列表预览 | 展示 `[文件] 文件名`；保留原文用于传输/CID 重试，私聊历史恢复文件卡片检查通过；截图审查触发并记录 |
| 同账号跨 Gateway 旧连接仍在线 | 批量 Redis presence 刷新确认 epoch 不匹配时只忽略结果 | 只在确认 kMismatch 时向原 I/O loop 排队替换通知，再次匹配原连接/UID/epoch；单条刷新路径相同处理；新会话不被误清理 |
| 本机 AI 不存在监听和模型 | 仅配置名称无法产生回答，Windows 未启动 Ollama | 在已授权后用已安装 serve 和 qwen3:0.6b；限制单并行/单驻留，只改子进程环境；保留下载、监听、模型摘要与生成证据 |
| 第一次新镜像构建失败 | Dockerfile FROM 的 sha256 字面值被解释为远程镜像名 | 精确核对已存在本地基础镜像标签及 ID 后构建；失败时无容器替换，原失败日志保留 |
| 后端分开提交被 preflight 拒绝 | 已写入的 Qt 新源码仍未进入 Git，仓库要求不遗漏源码 | 不绕过钩子；审计后仅撤销本任务 15 文件的暂存状态，完整功能验证后将前后端明确清单一并提交；工作区源码未回退 |
| 一次最终自检没有生成报告 | 启动测试脚本提前创建证据目录，测试按保护要求拒绝覆写 | 保留 attempt5 的退出码 2，随后给自检一个不存在的目录；仅属于测试调用错误 |
| 私聊回归读取错误报告名 | 驱动误读 report.json，原有自检实际写 summary.json | 核对真实 summary、进程退出码和空 Qt stderr；后续驱动按实际文件名读取 |

旧版私聊的 NoProxy、消息竞态去重、析构回调堆损坏、QSharedMemory 原子账号占用等修正继续保留在基线。新增功能不改变全局代理和系统 Qt 安装。

## 每轮源码和原始结果保存

`qt6-ui-features-20261007-attempt1` 至 `attempt9` 均保存源码快照和构建日志，成功轮次还保存状态/协议结果、DLL 部署日志和设计截图。真实功能 `qt6-features-e2e-attempt1` 至最终轮次保留 progress、原始事件、报告、进程结果、专用账号任务与文件。早期失败目录不被删除或以新成功覆盖。`.local/codex/feature-candidate-*` 保存每次 guest 写入前的文件；runtime 目录保存部署前 identity/mount/config 审计和构建日志。

公开 JSON 仅导出检查名称/通过状态、二进制/源码摘要和证据位置。原始消息事件可能包含有效附件能力，私有会话/配置留在本机证据和 guest `.local`，不进入 Git。最终交付新增统一 iteration ledger，列明每轮构建与验证状态。Git 只提交核对过的业务代码、文档、启动助手和去敏结果；不 push。

## 主机/部署审计与可恢复性

写源码前保存原文件 SHA 与 preimages，guest 应用前再次比对 HEAD、原始修改和每个 preimage。保留原有 3 个未提交 benchmark 修改以及 `.env.example`，不暂存它们。新增测试数据仅属于本任务账号，不删旧账号、不读旧密码、不清表。

原 19 个正常服务保留，替换 MessageService 与两 Gateway 使用原配置/挂载；旧容器重命名并停止保留。新文件服务为第 20 个角色，文件服务 v2 与修正 v3 旧容器也保留。所有替换保存精确镜像/容器 ID；助手核对最终 accepted-runtime 再启动，不能盲目 Compose 重建。

回退必须先读对应 runtime audit 并核对目标 ID、镜像、挂载和角色。候选容器应审计后停止并另名保存，再恢复其指定备份名称启动；不得删除数据库、卷、测试文件或无关容器。当前正常运行的已验收服务不需回退。密钥为文件分享专用随机 32 字节、0600、非符号链接，存入私有受限目录；客户端和 Git 都不保存此服务密钥。

文件容器发布在 VM 私网 IP:18082，rootfs 只读、UID1000、无额外 capabilities、no-new-privileges、内存384 MiB/PID128，专用 state 挂载写权限；入口有请求/范围/会话/队列/登录速率上限。资源没有以删除缓存或结束游戏方式获得；其他应用保留，不改未来本机启动/系统环境。

## 仍需推进的明确边界

- 群持久化已读回执/跨设备未读同步尚缺，本地群未读不能冒充服务器事实。
- 好友/会话当前客户端一次读取上限分别 100/50，在线订阅和全量分页、持久化草稿、跨设备任务同步需继续实现。
- 文件单次64 MiB、每账号本地100任务；入口1024登录会话、8小时过期、每IP登录30次/分钟是本机功能部署限制，不能承接未经评估的50k文件活跃用户。
- 群当前 UI 新建默认100成员；分页不等于大群广播容量验收。
- Qt 当前9000与文件18082使用私网明文；已有9443服务端TLS入口尚未接入Qt，公网发布前必须完成传输与证书方案。
- AI 直接Ollama问答只读取已加载20条上下文，尚非完整MCP Agent工具链；0.6b模型生成质量、长上下文、并发与GPU资源未独立验收。
- 小规模功能回归未测10k–50k、p95/p99/最大QPS或所有高并发交叉工作负载。本轮没有可用于简历的新增容量结论。

本轮交付可以演示真实多用户私聊、群聊、文件与AI的完整常见流程。简历可如实表述新增的鉴权、幂等、断点续传、哈希验收、消息快照ACL、异步Qt与跨网关会话修复，并引用检查证据；容量和极限延迟仍应引用专门压测的有效结果。
