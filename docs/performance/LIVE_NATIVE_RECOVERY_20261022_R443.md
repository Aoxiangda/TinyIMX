## R442：已确认消息与遗留事件的真实进程故障

1. 在保留的同一原生数据上，将发布 worker 设为 1，以构造有界后台排队场景；这不是性能对照或推荐默认值。
2. 独立 C++ 客户端以 8 个发送线程完成 128 次持久化 RPC，逐项验证成功结果、MID 和 128 字节正文。客户端在输出完整成功集合后保留 channel，等待父进程发出故障。
3. 父进程核对目标 PID 的命令行和 `/proc/<pid>/exe` 哈希后，仅对这个新建测试 Message 进程发送 SIGKILL，确认退出为 -9。原服务没有收到信号。测试日志没有正常 drain 记录。
4. 独立确认旧 SQL owner 锁已释放后，以 8 个发布 worker 启动同一候选、同一存储。所有 128 次重试返回幂等复用，MID 数组与故障前完全相同，正文一致。
5. 实际补发 35 个遗留原生事件。projector 处理并确认 129 条记录，处理/ACK 错误均为 0；缓存为 `[0,132,132]`。恢复后新消息计数为 0，最终待发布、隔离和持有事件均为 0，正常退出。

这里验证的是 Message RPC 持久化成功边界。未将它描述为已验证 Windows 客户端的完整端到端 ACK/投递链。
