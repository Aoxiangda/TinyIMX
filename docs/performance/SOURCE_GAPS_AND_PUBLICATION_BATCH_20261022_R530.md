## 4. 本轮代码候选及工程验证

`publication.progress_batch_size`缺省仍1，上限16且不得超过max_held。worker仅取得已经排队的最多N条；Broker确认成功的ID才进入同一进度批次；失败/重试/隔离的ID不混入。held ownership保持到进度写完成，避免旧扫描快照重复准入。正常停机完成当前Publish，留下其余未尝试事件；进度最后WAL同步。异常发生在批次中途时保留可重放事件，容许同身份、同正文重复投递。

### 16.2 PERF-768.1：每条消息承担的工作多，C++与epoll不能抵消这些成本

固定peer的`onSend`依次permission、persist、sendack；消息追加进入本地BatchDB。`loop`只收集已就绪项，最多100项，最终`Commit(pebble.Sync)`成功才通知等待者。这里不是跳过持久化，也不是一定每次都能凑到100条。

Tiny当前native候选虽然将私聊消息移入本地存储，仍有：网关业务排队和权限权威读取、Message RPC准入/处理、CID旧排序规则SQL查询和用户存在检查、本地消息/状态/事件写入、接收确认再次持久化、外部RocketMQ发布和发布进度、本地owner快照/Redis未读投影。它们包含相互独立的正确性责任，也存在可减少的重复访问、序列化和调度成本。不同合同必须披露，不能据此为全部差距免责。

源码位置：[身份查询](../../services/message/local/MySqlLegacyIdentity.cpp:94)、[消息同步写](../../services/message/local/LocalPrivateStore.cpp:379)、[接收确认](../../services/message/local/LocalPrivateStore.cpp:681)。上游本地主来源：`<LOCAL_EVIDENCE_ROOT>/peer-source-build-20261020-r90/upstream/WuKongIM-a888f89533d0e7d1b2030e06504ca97f1ad891d4/pkg/wkdb/wukongdb.go`的BatchDB.loop/executeBatch，以及`internal/channel/handler/event_onsend.go`、`internal/user/handler/event_recvack.go`；R721已验证固定源码哈希。

### 16.3 PERF-768.2：顺序队列放大前驱等待，更多线程不能自动消除

### 16.4 PERF-768.3：后台发布串行等待和进度锁争用会反压前台

### 16.5 PERF-768.4：扩大队列只能推迟失败，不能提高持续排空速率
