QPS 与有效正文吞吐

业务 QPS 按完整消息计数。一条消息产生的 ACK、接收确认、心跳、RPC 和 MQ 操作各有职责，统计业务吞吐时保持一条消息一个分母。

1,000 QPS = 300,000 条 ÷ 300 秒
1,250 QPS = 375,000 条 ÷ 300 秒

1,000 × 128 B = 128,000 B/s = 0.122070 MiB/s = 1.024 Mbit/s
1,250 × 128 B = 160,000 B/s = 0.152588 MiB/s = 1.280 Mbit/s

含最后消息收尾的实测时间分别为 300.0067414 秒和 300.0128763 秒，因此完整完成速率为 999.978 与 1,249.946 条/秒。完整窗口内实际正文吞吐为 127,997.440 与 159,991.467 B/s。

正文每条 128 B，表中 KB / Mbit 使用十进制，MiB 使用二进制。上述为单份有效载荷，网络总流量另含协议、中间件和心跳开销。

环境与消息语义

Windows 原生 TIMX 客户端与 Ubuntu VMware 虚拟机共用物理宿主机。服务端固定 8 vCPU / 16 GiB，双 Gateway 均衡承载，每对私聊用户位于同一 Gateway；跨 Gateway 正确性由业务套件另行覆盖。

Native 私聊存储将消息、索引、未读真值和待发布事件原子同步提交；RocketMQ 使用 LOCAL / SYNC_FLUSH，发布器 8 线程、64 在途、16 条进度上限，SEND 逐条发送。MySQL 保留账号、关系、群、文件及逻辑引用，Redis 保存路由与未读投影。

50,000 连接采用 15 秒心跳，约 3,333 次/秒。全窗口参与指所有账号在测量窗口内收发；平均每用户每分钟分别发送 1.2 与 1.5 条。

本次范围为两个已完成的 300 秒小消息工作点。发布数字保留实际配置与持续时间。
