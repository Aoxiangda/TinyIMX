## 已定位的因果链

1. **PERF-1441：原有计时漏掉多输入路径。** 旧分析中约19%—23%的请求进入多输入批处理，

   两轮120000条实际持久化、内容、身份、接收确认及原20服务恢复均完成。
2. **PERF-1486/1480：固定用户模8分桶阻塞无关会话。** 8个工作线程各自只处理一种from_uid模8值。
   实际一条请求排队20.217ms，其中20.042ms与该线程处理其他会话的执行重叠；两轮分别保存66/103条此类证据。
   其他空闲线程不能接手。该问题有源码和真实RPC时间线的共同证据。
3. **PERF-1468-C2：慢前驱放大会话顺序等待。** 一条ACK75.3128ms中网关等待55.050ms，

4. **PERF-1468-C3：Tiny批的是完整RPC准备，peer批的是已准备好的KV写入。**
