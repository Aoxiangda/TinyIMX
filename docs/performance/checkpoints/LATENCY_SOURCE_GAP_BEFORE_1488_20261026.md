## 已定位的主要链路与此前遗漏

PERF-1441：实际冻结LocalPrivateStore多输入路径没有原生阶段计时。旧399/367条同MID分解只
覆盖标量/回退，遗漏了两轮约18.90%/23.00%的请求。之前用其几毫秒分位数解释全局高延迟，
覆盖不足，现明确更正。两个同批RPC执行101.949/102.317ms，该工作线程期间无WAL调用；
这说明需要拆批内准备、锁与引擎等待，不能把102ms全部归为SQL或磁盘。

PERF-1440：同会话前驱RPC124.398ms，下一条排队136.901ms，其中136.714ms与前驱活动重叠。
FIFO确实放大前驱慢处理；不能通过破坏会话顺序去掉这段等待。此为选中样本，不是总体分位数。

固定上游合并已准备KV写；本项目前台队列合并整个RPC，顺序执行SQL身份、加锁、引用检查，
最后同步提交并整组返回。这是可定位、可消融的代码差异。另有Outbox→外部MQ→投影→RPC→
Redis与持久化接收确认的工作差异，保持完整业务后分别优化，不用语言差异解释。
