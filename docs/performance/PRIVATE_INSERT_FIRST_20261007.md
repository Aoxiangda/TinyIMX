# 私聊唯一约束优先候选与本轮失败记录（2026-10-07）

当前候选默认关闭，尚未完成性能验收。目标是消除新私聊持久化前的一次重复查询，不放宽认证、权限、持久化、Outbox 或成功 ACK 条件。

原路径在已经取得健康 MySQL 租借后，先按 `(from_user_id, client_message_id)` 查询；未命中后事务插入又由同一 UNIQUE 索引仲裁。候选直接进入原事务插入路径，新消息少一次 SQL 查询；重复键仍经过原回滚、归还连接和完整记录恢复，比较 MID、发送者、接收者、内容及类型。已有消息的重复请求会多一次插入尝试，这是必须记录的代价，不能只测新消息后宣称所有场景更快。

`TINYIMX_PRIVATE_INSERT_FIRST_ENABLE` 只有严格字符串 `1` 启用；不改变类布局或公开接口，不跳过好友权限、不缓存身份、不合并或提前提交、不修改 Redis 健康检查。先用真实隔离 SQL 的原幂等、竞争、Outbox 回滚、读状态及错误用例验证；再使用同一 ELF 的开关对照。没有证据前保持正式运行镜像与开关。

当前版20k基线第一轮：20000个连接登录已完成；会话页派生场景标签与原客户端固定断言不一致，客户端在发送业务前失败，父控制器中止。该失败不能作为完整稳态性能结果。原始客户端日志、部分消息 ledger、资源采样、失败及19实例保护记录保留。更正只保留客户端要求的 `mixed20k-ON` 内部标签，外层目录及run ID独立，避免覆盖旧证据。

此次中止同时发现协调器遇到空文本异常（例如 `KeyboardInterrupt()`）时，`failure=str(e)` 为空，漏写失败汇总，随后引用尚未生成的 `gates` 抛出 `UnboundLocalError`。新增派生协调器使用异常类名补齐空文本，保留原文件、所有门槛与超时；测试通过调用实际 `run` 函数注入五种首个失败，模拟外部依赖，验证非零退出、原失败、abort标记和汇总，而非复制实现来测试。

后续结果附实际原始请求计数、尾延迟、SQL读写代价与恢复身份。所有功能10k–50k目标仍未完成，不以本候选代码提交宣称收益。
