## 已落实的控制链

`run_sdk_formal_control_r260.py` 采用独立文件，不覆盖R175/R212。同一九程序、固定SDK字节，三个MQ角色统一使用只读SDK挂载和显式加载优先路径。

1. 停止原应用前，九个候选ELF做依赖加载检查；三个MQ角色必须解析到固定SDK挂载目标。
2. 克隆角色启动后、READY_RELAY放行前，检查实际运行进程的SDK映射、设备号/inode、文件SHA和只读挂载。启用init时沿有限进程树找到确切应用，不能拿tini的映射冒充应用。
3. 工作线程退出后保留投影程序的静止SDK统计。解析失败只记录拒绝状态，不中断原服务恢复。正常完整轮的资格校验另要求应用处理/ACK无失败，实际提交项与投影应用数一致、请求提交与终态一致。
4. 旧SDK、新SDK OFF、新SDK ON分别验证能力存在、快照可用、两个批量开关和新API计数。计数范围始终为process_global_new_api_only，不是Broker总RPC，也不是前台持久化ACK延迟。

`run_sdk_formal_point_r260.py` 保留Windows原生R8客户端、10000连接、700条/s、60秒、128字节、原8GiB启动/6GiB测量门槛。启动前强制验证R212四组完整限页控制及其原始证据哈希，不能跳过前序阶段直接测SDK。SDK阶段固定index1、demand0、held0、empty0、snapshot0、lazy0，只改变规定的SDK版本/线协议开关。
